# A · 环境、运行条件与校准

**目标**　在正式语料之外测得设备参数，并给另一位同学足够的信息重建环境。确认设备是 RTX 3090 Ti，记录 GPU UUID、可见显存与持久存储路径。

1. 记录 GPU 名称、UUID、计算能力、SM 数、显存、L2 大小、驱动、功耗上限、时钟策略、CPU、OS、Python、PyTorch 构建版本与 git SHA、CUDA runtime、Triton、编译工具版本。分别记录驱动支持的 CUDA 版本和框架构建版本。采集 GPU 查询原文、包锁、项目提交号和未提交补丁；记录设备选择与编译缓存目录。
2. 记录主机系统版本、显示会话状态和持久盘挂载点。在主机上建立环境与缓存。单进程、单 CUDA stream、推理模式、静态 shape、连续张量。关闭 autocast、自动 CUDA Graph 和会在正式调用中调优的选项。保存各项配置的**实际取值**及读取位置。编译一个小图，检查 trace 确认普通模式逐 kernel 提交，再单独测试可手动 capture/replay 的路径。
3. 记录其他 GPU 进程及采集前后温度、功率、核心/显存时钟。正式计时时使用同一功耗和时钟策略，按约 1 秒周期记录遥测。无法锁频时保留实际频率；有外部任务进入 GPU 或发生节流状态切换的 block 标记污染并整块重测。记录首个尝试。
4. 完成下表校准。使用与正式测试相同的 stream、事件时间单位和提交路径，先预热。普通启动与 replay 分开计量，各配置 20 个独立计时块，保存原始总时间、调用次数和计量顺序。

| 参数 | 操作 | 导出量 |
|---|---|---|
| L，普通启动 | 用相同 host launcher 在 stream 上依次发出 k 个最小 kernel，k 取 1、8、32、128，验证 trace 中调用数。每个块重复整段以达到毫秒级 | 对各 k 的每段耗时中位数做带截距线性拟合，斜率以 µs/kernel 表示；保存截距、残差和 launcher 类型。它是该提交路径的有效增量 |
| L，replay | 分别 capture 含 k 个同样 kernel 的图，重复 replay 单张图计时 | 同上。用于判断提交模式变化；分别列出 capture 和测量路径 |
| BW，有效复制带宽 | 预分配输入输出，以连续 copy kernel 读取和写入各 S 字节。S 从 256 B 起按 2 倍递增至 512 MiB。每个尺寸固定缓冲区反复使用，核实输出和调用数 | BW = 2S / 每次耗时，统一存 bytes/µs。记录缓存复用条件。小尺寸值包含启动成本，单列作诊断 |

主模型取最大三个 S 的有效带宽中位数作为同一卡的 BW，检查这些尺寸超过 L2，报告三值及离散程度。此标定减少小尺寸 copy 启动与模型启动项的重复计入。若启动斜率非正或大尺寸校准异常，先查事件边界、单位、缓存和设备状态；保留异常记录，校准未通过的模型列为不可评估。

**验收**　环境可由锁文件重建；普通与 replay 的 trace 能区分；两张校准曲线均可由原始块重算。可选性能计数器权限单独记录，缺失不阻塞主计时。[PyTorch CUDA 异步执行与 Graph 语义](https://docs.pytorch.org/docs/stable/notes/cuda.html)
