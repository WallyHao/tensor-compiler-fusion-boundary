# B · 语料、局部切边与正确性

**实验单位**　每个 case 是模板、shape、dtype、布局和一条命名边的组合。仅返回 y，t 是单消费者中间值。常数为固定标量。x 为连续行优先输入。

| 模板 | 生产者 t | 消费者 y | 形状网格 |
|---|---|---|---|
| P1 | x × 1.25 + 0.25 | relu(t) | x 为 [N] |
| P2 | tanh(x) | t × 0.75 + 0.25 | x 为 [N] |
| R1 | sum(x, dim=1, dtype=float32) | relu(t) | x 为 [M,K]，t 为 [M] |
| R2 | amax(x, dim=1) | t × 0.75 + 0.25 | 同 R1，t 保持输入类型 |

- N 取 1024、8192、65536、524288、4194304、16777216；M 取 16、256、4096；K 取 128、512、2048、8192。dtype 取 float32、float16。共 24 个逐元素配置和 48 个归约配置，共 72 个 case。分组键为 P1/P2/R1/R2，各组内的全部尺寸和精度同进同出。
- 试点固定为 P1/N=65536/fp32 和 R1/M=256/K=512/fp32。每个 case 先生成 manifest，附生产者、消费者、边名、t 的 shape/dtype、预期输出和逻辑读写字节。记录 split 时 t 的真实物化类型；逻辑节省按一次写 t 加一次读 t 计算。

## 三种策略的产物

1. **default**　先编译原始单图，保存 FX 图、lowering 后和调度前后 IR、生成的 wrapper 与 kernel 源码。映射 t 的写入和读取，标明默认选择、选择发生的 pass、源码版本与位置。若已在 lowering 内联，明确记录发生层级。
2. **split**　保留具名边，使生产者输出物化、消费者启动另一个 kernel。优先在固定版本的 lowering 阶段对 t 请求 materialization，并在调度器仅阻止跨该边合并。**fused** 使用同一入口与配置，让可合法合并的生产者和消费者跨边生成代码；默认已经满足某一策略时可复用该产物。保留局部改动 diff、边匹配条件和命中日志。所有策略使用隔离编译缓存，记录图断裂、回退和重编译。
3. 对每种策略分别生成算子 → 调度节点 → kernel 的关联表，列出执行次序、grid、block、寄存器数、静态/动态 shared memory、中间缓冲区及跨边读写。另取一次非计时 trace 检查实际发射。split 证据为 t 的独立写入和随后读取；fused 证据为同一 kernel 内目标生产消费与跨边物化消失。多阶段归约可有共同的前置 kernel，需逐项核对其分区一致。
4. 主实验要求相同单图入口、同一编译栈、相同其余分区，允许目标区域因融合改变 tile 和资源分配。全局禁融合、拆为两个 Python 调用或手写 Triton 可用于诊断；单独归档。若候选不合法、两个策略生成同一分区或出现无关重写，登记原因。默认策略若形成第三种分区，记录原貌并从默认二选一评价中移出。

## 数值验证

对每个输入固定 CPU 随机种子 17、29、43，生成 [-1,1] 均匀样本，先转为目标 dtype；再加一组全零输入。用 eager 执行同一表达式为参考，另以 float64 检查归约误差。FP16 逐元素在物化处舍入可能改变低位，保留误差。shape、dtype、有限性逐一核对，记录最大绝对及相对误差。预设与 eager 比较的 (atol, rtol)：fp32 逐元素和 amax 为 (1e-6,1e-5)，fp32 累加求和为 (2e-4,1e-4)，其余 fp16 输出为 (2e-3,2e-3)。失败样本保存种子、误差位置与复现命令。replay 在 capture 后至少核对一次相同输入输出。

**验收**　72 行 manifest 全部有状态；有效行可凭 IR、trace 和正确性记录判定两种策略确实比较了同一条边。另交一份适合课堂展示的切边图和对应源码片段。
