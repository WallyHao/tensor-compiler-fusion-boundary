# 01 · 语料与候选

## 固定配置

| 组 | 个数 | 设计与对照 |
|---|---:|---|
| `anchor` | 4 | R1/R2 各取 M=16、256，K=8192，连续 FP32。用原始 case ID 在本轮重新编译、测量，并对照归档中的同 ID |
| `long` | 8 | 在四个同期对照上分别把 K 延长到 16384、32768，固定模板、M、dtype 和布局。观察并行调度、临时缓冲区和收益随 K 的变化 |
| `layout` | 4 | 与四个同期对照形状和元素逐一相同。输入是由 K×M 连续存储得到的转置视图，逻辑形状 (M,K)，物理 stride (1,M)，沿逻辑轴 1 归约 |
| `rmsnorm` | 4 | 新模板 N1，M∈{16,256}，K∈{4096,8192}，连续 FP32。取 RMSNorm 的行均方到逆 RMS 因子这条边，`t = mean(x.square(), dim=1)`，`y = rsqrt(t + 1e-5)`。研究对象为该算子片段到逆 RMS 因子的输出 |

各策略保持相同输入、FX 语义、编译开关和 dtype。R1/R2 复用已有算子函数、容差和逻辑字节定义。N1 使用 FP32 累加，`t` 和输出形状均为 (M,)，逻辑节省为 `8*M` 字节。对照 eager、FP64 及零输入。零输入参考值为 `1/sqrt(1e-5)`。N1 预设 `atol=2e-4`、`rtol=1e-4`，使用种子 17、29、43 和零输入。布局组用相同 seed 构造逻辑值，再在被测图外复制进 stride 为 (1,M) 的存储。对编译示例、校验输入、正式 direct 和 replay 输入断言 shape、stride、dtype 相符，并记录实测输入步长和图内真实的布局转换。

## 接入现有程序

1. 以 [cases.csv](cases.csv) 为唯一配置来源，导出补采用 `cases.jsonl`，写入 20 个 case 的组、形状、输入 stride、控制 ID 和 pilot 字段，计入校验和。原 `build_corpus()`、默认 `--all` 和既有 case ID 维持 72 条的行为。
2. 让编译入口、独立 worker、`CandidateStore` 和 `FusionBoundaryProvider` 读取同一份显式清单。当前候选路径使用内置语料查 ID，单独写一份 JSONL 不能让新配置自动加载。检查 `fb/corpus.py` 对模板和布局的校验分支，把 N1 和转置布局接入补采路径。收集时显式传逗号分隔的 ID，避免模板缩写或默认网格漏选。复用原有校验、计时和封存。
3. 先在 CPU 检查 20 行清单均能往返读取，布局与对照逐元素相等，N1 的 eager 与 FP64 满足预设容差。运行现有测试，验证默认清单及候选接口兼容。检查三种试点可以从独立 worker 流转到测量端。记录实际命令、依赖及 commit。

## 切边验收

1. 每个 case 计划独立编译 `default`、`split` 和跨过指定边的 `fused`，最多 60 个变体。默认策略须保留独立编译证据并记录映射。
2. 保存 FX 和调度片段、生成 kernel、切边命中、编译/实际 launch 序列、参考校验与算子输出。显式核对 `split` 写出并重读指定的 `t`，以及 `fused` 取消该物化。长归约允许有两种策略共有的分块归约阶段。只有证据能解释这些阶段且其他分区未改变，才进入主配对。
3. 记录无法定位切边、上游调度随策略一起改变、默认第三种实现、数值失败等具体原因。无法配对的行保留在清单，标记 `excluded`。默认第三种实现可保留可比的 split/fused 结果，默认选择与 regret 在该行标为未覆盖。编译失败和不适用配置按模板汇总。克隆、断图及全局关闭融合的结果只能作诊断。
