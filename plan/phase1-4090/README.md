# 第一阶段工作单 · RTX 4090

在租用的云端 RTX 4090 上交付可以独立复核的 TorchInductor 局部切边研究。这里的路径、计数和样本阈值是工作约定，实验结果由执行者填写。[完整项目计划](../../docs/research-plan.md)

| 分发顺序 | 工作单与负责人 | 接收条件 | 交付给下游 |
|---|---|---|---|
| A | [环境与校准](01-environment.md)，测量 | 可登录配有 RTX 4090 的云实例 | 环境清单、锁定版本、校准原始行 |
| B | [语料与编译](02-candidates.md)，编译 | 可先在 CPU 上写生成器，设备核验依赖 A | 全量语料清单、试点、策略产物与切边证据 |
| C | [配对测量](03-collection.md)，测量 | A 和 B 的试点通过 | 每个合格样本的原始配对行、遥测、诊断 |
| D | [数据契约](04-data.md)，三方共用 | 开工即读取 | 统一主键、单位、状态、完整性检查 |
| E | [分析与交接](05-analysis.md)，分析 | 可先用标明 synthetic 的夹具验证读表，正式分析依赖 C/D | 单卡报告、复跑记录、跨卡冻结包 |

**先做试点。** 普通启动下各跑通一个逐元素和一个归约样本，检查输出、切边、时间单位及配对关系。把试点结果独立存档。试点通过后锁定协议，用新 run 正式采集，包括重新测量试点尺寸。若某类无法构造，在同类第二个模板上定位原因；仍失败时保留失败覆盖表，另一类可继续，单类结果标为部分完成。

**交付位置。** 执行时在仓库中维护可复跑的实验入口和依赖锁；大数据写入执行主机的持久路径 `runs/<run_id>/`。释放实例前，将原始数据、编译证据、环境锁与冻结包导出至团队可访问的持久存储，核对文件清单和 SHA-256。每位执行者提交调用命令、输入清单路径、输出路径、成功/失败数量及一个可追溯的 case_id。并行开发可行，GPU 校准、编译调优、正式计时、profiler 与复跑依次独占同一设备。

**结束条件。** 语料清单中的每个配置都有最终状态；主分析使用的每个配置均有成对编译证据、正确性和原始时间。报告注明两类覆盖率、无法判定的比例、可复现的主要结论及其限制。交给下一阶段的是版本化冻结包。单卡报告可独立交付；跨设备验证视后续资源而定。

## 本地开发与云端执行

1. 本地编写语料生成器、编译与采集入口、数据校验和分析脚本。用 CPU 参考算子和标记为 synthetic 的夹具检查形状、记录格式、配对及绘图。
2. 将试点代码提交到 Git 并同步到云实例，记录实际运行的 commit。先在 4090 编译两个试点并检查 IR、kernel trace 和输出；根据日志在本地修改后同步。试点通过再扩大到全量语料。
3. 在 4090 完成校准、计时和性能诊断。通过平台网页终端、作业服务或 SSH 启动作业，具体入口取决于平台。长任务使用作业服务或 tmux，日志和结果写入持久盘；下载后可在本地重建表图。
